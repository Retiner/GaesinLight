레벨 제작 가이드

RGB 손전등으로 블록을 비춰 능력을 발동시키고, 버튼·발판·문을 연결해 퍼즐을 만드는 게임입니다. 이 문서는 레벨에 블루프린트를 배치하고 Details 패널에서 설정하는 방법을 설명합니다.

스테이지 흐름: 맵에서 손전등·색 필터를 주움(줍기) → 퍼즐을 풀며 진행 → 통로의 트리거로 다음 맵으로 이동(트리거). 맵 끝에서 가진 필터를 테이블에 반납하면 출구가 열림(반납 테이블).

읽는 법: 표의 변수는 레벨에 배치한 인스턴스의 Details 패널에서 바꿀 수 있는 값입니다. Details 패널에 보이지 않는 변수는 내부 계산용이라 건드릴 필요가 없습니다. 각 장 끝에 "이렇게 만들 수 있어요" 예시가 있습니다.

0기본 개념: 신호 연결

퍼즐 장치는 보내는 쪽(송신)과 받는 쪽(수신)으로 나뉩니다.

역할BP하는 일
송신BP_Button, BP_PressurePlate, BP_Trigger, BP_Pickup, BP_FilterReturnActivate(켜짐) / Deactivate(꺼짐) 신호를 보냄
수신BP_Door, BP_Door2, BP_Light, BP_Light2, BP_AvilityBlock, BP_Hatch신호를 받아 열림 / 켜짐 / 이동 등 반응
연결하는 방법
  1. 레벨에서 송신 장치(버튼, 발판, 트리거, 줍기 아이템, 반납 테이블)를 선택합니다.
  2. Details의 SignalTargets 배열에서 + 를 눌러 칸을 추가합니다. (BP_Trigger만 이름이 Targets입니다.)
  3. 칸을 펼쳐 Target 옆 스포이드 아이콘을 누르고, 뷰포트에서 수신 장치(문, 다락문, 광원, 블록)를 클릭합니다.
  4. Channel에 몇 번 채널로 보낼지 적습니다. 보통은 0(그 장치의 기본 기능) 그대로 두면 됩니다.
  5. 여러 장치를 동시에 움직이려면 칸을 여러 개 추가하면 됩니다.
채널
  • 수신 장치는 기능마다 채널 번호가 정해져 있습니다(장치 BP에 고정, 레벨에서 바꾸지 않음). 0번은 항상 그 장치의 기본 기능입니다. 어떤 기능을 켤지는 송신 장치의 Channel로 고릅니다.
  • 채널 번호는 받는 장치 안에서만 의미가 있습니다. 문의 1번과 광원의 1번은 서로 다른 기능일 수 있습니다.
  • 송신 장치 2개를 같은 수신 장치의 다른 채널로 연결하면, 각각 다른 기능을 켜고 둘 다 켜면 두 기능이 함께 동작합니다.
  • 같은 장치를 다른 채널로 두 칸 넣으면, 버튼 하나로 그 장치의 기능 두 개를 동시에 켤 수 있습니다.
  • 채널마다 신호를 따로 셉니다. 1번 채널 신호는 0번 기능에 영향을 주지 않습니다.

장치별 Channel → 기능 표는 신호 채널 한눈에 보기에 있습니다.

예: 발판 → 광원 Channel 0 + ReOn 버튼 → 같은 광원 Channel 1 = 발판을 밟아 불을 켜 두고, 버튼으로 색을 고르는 퍼즐

SignalTargets 알아둘 점
  • 스포이드 대신 칸의 드롭다운에서 레벨에 있는 액터 이름을 골라도 됩니다.
  • 반응하는 것은 신호를 받을 수 있는 장치(문, 다락문, 맵 광원, 능력 블록)뿐입니다. 벽이나 일반 메시를 넣으면 오류 없이 그냥 무시됩니다.
  • 빈 칸(None)이 있어도 문제는 없지만, 헷갈리지 않게 지워 두는 것이 좋습니다.
  • SignalTargets가 비어 있으면 버튼을 누르거나 발판을 밟아도 아무 일도 일어나지 않습니다.
  • 신호는 상태가 바뀔 때만 보냅니다. 예를 들어 발판에 두 번째 물체가 올라가도 이미 켜져 있으면 신호를 다시 보내지 않습니다.
  • 수신 장치를 복제(Alt+드래그, Ctrl+D)해도 SignalTargets에는 자동으로 추가되지 않습니다. 새 장치는 직접 넣어야 합니다.

ChannelRequired채널별 필요 신호 수 (키 = 채널 번호, 값 = 개수). 이 수 이상 모이면 켜지고, 아래로 떨어지면 꺼짐장치가 받는 채널마다 1 (문 0, 1 → 1, 다락문/블록 0 → 1, 광원 0~4 → 1)
  • 값 1 → 연결된 송신 장치 중 하나만 켜져도 동작 (OR)
  • 값 2 → 두 개가 동시에 켜져야 동작 (AND)
  • 예: 광원 ChannelRequired의 1 → 2 → 전원(0번)은 신호 1개, 색 변경(1번)은 신호 2개가 필요
  • 목록에 없는 채널은 1로 처리됩니다. 값이 0 이하여도 1로 처리됩니다.
  • +를 누르면 0 → 0 칸이 생깁니다. Map은 같은 키를 두 번 가질 수 없으므로, 새 칸을 넣기 전에 기존 칸의 키를 다른 번호로 바꿔 두세요.
  • 여러 송신 장치가 같은 수신 장치의 같은 채널로 보내면 신호가 합산됩니다.
버튼과 발판을 한 장치에 같이 연결하기

버튼과 발판은 같은 신호를 보내므로, 둘 다 같은 수신 장치(같은 채널)를 SignalTargets에 넣을 수 있습니다. 종류를 섞어도 똑같이 합산됩니다.

  • 문(ChannelRequired 0 → 1) + 버튼 + 발판 → 버튼을 누르거나 발판을 밟거나, 둘 중 하나만 해도 열림 (OR)
  • 문(ChannelRequired 0 → 2) + 버튼(Togle) + 발판 → 버튼을 켜 두고 발판에 블록을 올려야 열림 (AND)
  • 문(ChannelRequired 0 → 2) + 버튼(Timed) + 발판 → 발판을 밟은 채 제한 시간 안에 버튼까지 눌러야 열림

AND 조건에 버튼을 쓸 때는 JustOn / Togle / Timed처럼 켜진 상태가 유지되는 모드를 쓰세요. ReOn은 즉시 꺼지므로 발판과 동시에 켜진 상태가 되지 않습니다.

1BP_Charactor — 플레이어

손전등을 들고 다니는 플레이어입니다. 맵에 어떻게 두는지는 그 맵의 GameMode에 따라 다릅니다: 본 게임용(BP_RealGameMode)은 시작할 자리에 BP_Charactor를 하나 놓고(Auto Possess Player = Player 0, Class Defaults에서 정해 두면 따로 안 바꿔도 됨), 테스트용(BP_TestGameMode)은 캐릭터를 놓지 않고 PlayerStart 하나만 둡니다. 자세한 순서와 주의사항은 9장 새 맵 준비.

3-2BP_Respawn — 블록·플레이어 되돌리기 구역 구역

보이지 않는 박스입니다. 들어온 Physics 블록은 게임 시작 때 위치로 되돌리고, 들어온 플레이어는 지정한 위치로 소환합니다. 둘 중 무엇을 할지는 구역마다 고릅니다. 신호와는 상관없습니다.

설정
변수설명기본값
ResetBlock켜면 들어온 Physics 블록을 시작 위치로 되돌림켜짐
ResetPlayer켜면 들어온 플레이어를 PlayerRespawnLocation으로 소환꺼짐
PlayerRespawnLocation플레이어 소환 위치. 뷰포트의 다이아몬드를 끌어서 정함 (구역 기준 위치라 에디터에서 구역을 옮기면 함께 따라감). 게임이 시작될 때의 자리로 고정되어, 게임 중에 구역이 움직여도(프레스) 소환 위치는 그대로구역 중심

크기는 액터 Scale로 조절합니다.

블록 (ResetBlock 켬)
  • 플레이어가 블록을 들고 지나가면 블록이 손에서 떨어지고 제자리로 돌아갑니다.
  • 던지거나 능력으로 날아간 블록, 보라 상태(통과 중)인 블록도 잡습니다.
  • 돌아간 블록은 멈춘 상태입니다 (날아가던 속도·회전 없앰). 크기·능력 상태는 그대로이고 원래 흐름대로 풀립니다.
  • Fixed/Patrol 블록(움직이는 발판·벽)은 지나가도 영향 없습니다.

블록의 시작 위치가 구역 안에 있으면 안 됩니다. 처음부터 겹쳐 있으면 되돌리기가 동작하지 않습니다.

플레이어 (ResetPlayer 켬)
  • 들어오면 세상이 멈추고(움직이는 발판·블록·프레스·물리 정지) 화면이 0.5초 동안 어두워진 뒤 PlayerRespawnLocation으로 순간이동하고, 다시 0.5초 동안 밝아지면서 세상이 다시 움직입니다 (맵 이동과 같은 암전, 2026-11-01). 프레스 블록과 동시에 닿아도 한 번만 일어납니다. 보던 방향은 그대로이고, 떨어지거나 날아가던 속도는 멈춥니다.
  • 블록을 들고 있었다면 먼저 손에서 놓습니다 (블록을 들고 함께 이동할 수 없음).
  • 다이아몬드가 바닥에 조금 묻혀 있어도 겹치지 않는 가까운 자리로 소환됩니다.

소환 위치는 구역 밖에 두세요. 구역 안이면 도착하자마자 다시 소환됩니다.

이렇게 만들 수 있어요
  • 스테이지 경계: 출구 문 바로 안쪽에 깔아서 블록을 다음 스테이지로 가져가지 못하게 함 (ResetBlock만)
  • 낙하 구덩이: 맵 아래에 깔고 ResetBlock + ResetPlayer → 떨어진 블록은 제자리로, 플레이어는 구덩이 앞으로
  • 함정 바닥: 다락문(IsDown) 아래에 ResetPlayer만 켠 구역 → 떨어지면 방 입구에서 다시 시작
  • 프레스(누르는 블록)는 이 구역을 손으로 붙이지 말고 전용 블록 BP_PressBlock을 쓰세요 (능력 블록 + 아래 감지 박스). 6장 프레스 블록
3-3BP_Pickup — 손전등·필터 줍기 송신

책상 위 등에 놓는 아이템입니다. 플레이어가 바라보고 F를 누르면 손전등이나 색 필터를 얻고, 아이템은 사라집니다. 얻는 순간 연결한 장치에 신호(켜짐)를 한 번 보내는 송신 장치이기도 합니다.

3-4BP_FilterReturn — 필터 반납 테이블 송신

맵 끝에 놓는 테이블입니다. 플레이어가 바라보고 F를 누르면 지금 가진 필터를 전부 반납하고, 연결한 장치에 신호(켜짐)를 한 번 보냅니다. 주로 "필터를 반납해야 출구가 열린다"는 스테이지 마무리에 씁니다.

설정

설정할 것은 이것 하나입니다. 어떤 색을 반납할지는 정하지 않습니다 (가진 필터 전부).

동작
  • 필터가 1개 이상 있어야 반납됩니다. 하나도 없으면 F를 눌러도 아무 일이 없습니다 (빈손으로 출구가 열리지 않게).
  • 반납하면: 손전등이 꺼짐 → 가진 필터가 모두 빠짐(그 색 키를 못 씀) → 테이블 위 그 색 자리에 필터가 나타남 → SignalTargets에 신호.
  • 손전등 자체는 반납하지 않습니다. 흰 빛(1)은 계속 쓸 수 있습니다.
  • 1회성: 반납한 테이블은 다시 반납되지 않고 F 대상에서도 빠집니다. 반납 기록은 레벨을 옮겨도 남아서, 같은 맵을 다시 열면 테이블이 반납이 끝난 상태로 시작하고 SignalTargets에 신호를 다시 보냅니다 (열렸던 출구는 다시 열리고, 잠근 문은 다시 잠김). 이때 테이블 위 필터 모양은 보이지 않습니다.
  • 테이블마다 따로 기록됩니다. 한 맵에 테이블을 여러 개 놓아도 됩니다.
  • 안내 문구(나중에 화면 UI에 표시): 필터가 있으면 "필터 반납", 없으면 "반납할 필터가 없습니다", 반납 후에는 없음.
  • 테스트용 GameMode 맵에서도 반납하려면 필터를 실제로 주워야 합니다 (테스트 모드의 "전부 사용 가능"은 반납 대상이 아님).

레벨에 놓은 테이블을 지우고 다시 놓으면 내부 이름이 바뀌어 예전 반납 기록과 연결이 끊깁니다. 저장 기능이 생긴 뒤에는 배포한 맵의 테이블을 다시 놓지 말고 옮기기만 하세요.

이렇게 만들 수 있어요
  • 스테이지 출구: 테이블 SignalTargets = 출구 문 Channel 0 → 필터를 반납해야 출구가 열림
  • 뒤로 못 가게: 같은 테이블에 지나온 입구 문 Channel 1(강제 닫기)도 추가 → 반납과 동시에 입구가 잠김
  • 다음 맵 준비: 반납 후 통로의 BP_Trigger로 다음 레벨 이동 → 다음 맵에서 필터를 다시 주움
3-5BP_LightSensor — 빛 감지 장치 송신

빛을 받으면 신호를 보내는 장치입니다. 정한 색의 빛이 ChargeTime초 동안 계속 비추면 켜지고, 빛이 빠지면 꺼집니다(발판처럼). 손전등, 맵 광원, 거울 빔을 모두 감지합니다.

2026-10-31: 능력 블록과 같은 반응 방식(서서히 밝아지며 충전 → 켜짐 → 빛이 빠져도 HoldTime초 유지 → 서서히 어두워짐, 크리스탈이 들어온 빛 색으로 변함)으로 바꿨습니다. 동작 확인.

5-1BP_Mirror — 거울

빛을 받아 반사 빔으로 튕겨 내는 거울입니다. 손전등, 맵 광원, 다른 거울의 빔을 모두 반사합니다. 반사 빔에 맞은 블록은 그 빛의 색으로 능력이 발동합니다.

배치
  • 앞면 = 액터의 초록 화살표(Y) 방향입니다. 앞면으로 들어온 빛만 반사하고, 뒷면은 빛을 막기만 합니다.
  • 거울판 크기는 Scale로 조절합니다: X = 가로, Z = 세로, Y = 두께. 반사 빔의 굵기 = 거울판 크기 그대로입니다 (판 모양 그대로의 사각 기둥).
  • 방향은 액터를 돌려서 맞춥니다.
  • 설정 변수는 없습니다. 빔 길이(3000)는 BP 내부 고정값입니다.
반사 규칙
  • 정면 기준 60° 안으로 들어온 빛만 반사합니다. 너무 비스듬히 스치는 빛은 반사하지 않습니다.
  • 반사 방향은 거울에 들어온 각도 그대로 꺾입니다 (입사각 = 반사각).
  • 빛마다 빔이 따로 나갑니다. 손전등과 맵 광원이 함께 비추면 각자 들어온 방향에 맞게 두 갈래로 반사됩니다. 한 거울에서 최대 3개까지입니다.
  • 빔 색 = 그 빛의 색. 흰 손전등 빛은 흰 빔으로 보이며, 블록에는 흰 빛 규칙 그대로 전달됩니다 (색을 더하지 않고 OwnColor 고유색만 발동).
  • 두 빔이 겹치는 곳은 안개 속에서 섞인 색으로 보입니다 (빨강 + 초록 → 노랑). 보이는 것만 그렇고, 블록 판정은 각 빔의 색 그대로입니다.
  • 한 블록에 빔 여러 개가 닿으면 색이 합쳐집니다 (빨강 빔 + 파랑 빔 = 보라).
  • 빔이 벽이나 물체에 가려지면 그 뒤로는 닿지 않습니다. 거울판 일부만 가려지면 남은 부분으로 나간 빛은 닿습니다.
거울에서 거울로
  • 반사 빔이 다른 거울의 앞면에 닿으면 다시 반사됩니다 (연쇄 반사).
  • 두 거울이 서로 마주 보고 있어도 빛이 무한히 오가지 않습니다. 나를 비추는 거울에는 내가 다시 빛을 보내지 않습니다.
  • 거울 3개 이상을 삼각형처럼 서로 이어지게 배치하는 것은 피하세요. 광원을 꺼도 빛이 남아 있을 수 있습니다 (아직 막지 않음).
알아둘 점
  • 빔은 레벨에 Volumetric Fog(안개)가 있어야 눈에 보입니다. 안개가 없어도 판정은 정상입니다.
  • 빨강·파랑 능력의 기준은 거울입니다 (거울 위치에서 밀려남, 거울 쪽으로 끌려옴). 플레이어 손전등이 함께 비추면 플레이어가 우선입니다.
  • 회전·이동 신호는 없습니다. 방향과 위치는 배치할 때 액터를 돌리고 옮겨서 정합니다.
이렇게 만들 수 있어요
  • 모퉁이 너머 비추기: 맵 광원 → 거울 → 벽 뒤의 블록
  • 색 모으기: 빨강 맵 광원과 파랑 손전등을 각각 거울로 반사해 한 블록에 모으면 보라
  • 거울 길: 거울 두세 개로 빛을 꺾어 멀리 있는 블록까지 전달

  • 버튼은 Togle·Timed, 또는 발판으로 연결합니다. "켜져 있는 동안 반대 방향"이라서, ReOn은 켜짐·꺼짐이 바로 이어져 두 번 돌아서므로 아무 변화가 없습니다.
  • 예: 발판(Channel 2) → 밟고 있는 동안 엘리베이터가 내려오고, 내려오면 다시 올라감.
  • 주의: 2번이 켜진 채로 1번 "처음으로"를 보내면 방향이 정방향으로 초기화됩니다.
  • 주의: PatrolReturn은 원래 끝에서 스스로 돌아서므로, 2번 신호는 켜질 때·꺼질 때 모두 "지금 방향에서 돌아서기"로 동작합니다.

Move가 Patrol 계열이면 블록 아래 SM_Floor_Plain_Light(표시등)가 보입니다. Fixed/Physics면 숨겨집니다. 움직이는 블록인지 한눈에 알 수 있게 하는 표시입니다.

MovePoint 설정 방법

Move가 Patrol 계열일 때 블록이 지나갈 경유지 목록입니다.

  1. 블록을 선택하고 Details의 MovePoint 배열에서 + 를 눌러 경유지를 추가합니다.
  2. 뷰포트에 경유지마다 작은 다이아몬드 모양 위젯이 나타납니다. 이것을 끌어서 위치를 잡습니다. (Details에서 X/Y/Z 숫자를 직접 입력해도 됩니다.)
  3. 블록은 배열 순서(0 → 1 → 2 …)대로 이동합니다. 순서를 바꾸려면 배열 칸을 위아래로 옮기세요.
  • 좌표는 블록 기준 상대 위치입니다. (0, 0, 300)은 "블록에서 위로 300". 그래서 블록을 옮기면 경로도 같이 따라 움직입니다.
  • 블록을 회전하거나 크기를 바꾸면 경로도 같이 회전·확대됩니다. 게임 시작 시 한 번 월드 좌표로 바꿔 두기 때문에, 이동 중에는 경로가 블록을 따라가지 않습니다.
  • 속도는 MoveSpeed(초당 이동 거리)로 일정하게 움직입니다. 경유지 사이가 멀수록 오래 걸립니다.
  • Move가 Fixed나 Physics면 MovePoint는 무시됩니다.
프레스 블록 BP_PressBlock

  • Details에서 바꾼 칸 옆에 생기는 노란 화살표(↶)를 누르면 BP 기본값으로 돌아갑니다.

새 맵 준비: World Settings · GameMode · 플레이어 배치

맵을 새로 만들거나 팀원 맵을 받으면 아래 순서대로 맞춥니다. GameMode를 무엇으로 고르느냐에 따라 플레이어를 놓는 방법, 시작 위치, 저장, 손전등 사용이 한꺼번에 정해집니다.

World Settings → GameMode Override
 ├ BP_TestGameMode (테스트) → PlayerStart 자리에 플레이어를 새로 만듦 → 빛 전부 사용 · 저장 안 함
 └ BP_RealGameMode (본 게임) → 맵에 놓은 BP_Charactor에 들어감     → 주워야 사용 · 체크포인트 저장·복원

① World Settings 열기

  • 레벨 에디터 메뉴 Window → World Settings (또는 툴바 오른쪽 Settings → World Settings). Details 옆에 World Settings 탭이 생깁니다.
  • Game Mode → GameMode Override 칸에서 아래 둘 중 하나를 고르고 레벨을 저장합니다. 이 값은 맵 파일에 저장되므로 맵마다 따로 정합니다.

② GameMode 고르기

GameMode쓰는 곳플레이어시작 위치손전등·필터체크포인트
BP_TestGameMode기능 테스트 맵PlayerStart 자리에 새로 생성PlayerStart줍지 않아도 전부 사용 (1~4 키 바로 사용)지나가도 저장 안 함, 복원 안 함
BP_RealGameMode실제 스테이지 맵맵에 놓은 BP_Charactor에 들어감 (새로 만들지 않음)놓은 캐릭터 자리·방향. 저장된 체크포인트가 이 맵이면 그 자리BP_Pickup으로 주워야 사용. 빛 꺼진 채 시작지날 때마다 저장, 다시 켜면 복원 (3-6장)

③ 플레이어 놓기

테스트 맵 (BP_TestGameMode)본 게임 맵 (BP_RealGameMode)
PlayerStart딱 하나 필요 (Place Actors → Basic → Player Start)쓰이지 않음 (있어도 무해, 지워도 됨)
BP_Charactor놓지 않음시작할 자리에 딱 하나. 바라볼 방향으로 Z 회전
Auto Possess Player-Player 0. BP_Charactor Class Defaults에서 정해 두면 맵에서 따로 안 바꿔도 됨 (맵에서 바꾼 값이 우선)

④ 다른 맵으로 넘어가는 경우 (BP_Trigger NextLevel)

  • 도착 맵도 ①~③을 똑같이 맞춰야 합니다. 출발 맵과 도착 맵의 GameMode가 달라도 됩니다.
  • 주운 손전등·필터, 반납 기록은 맵을 옮겨도 유지됩니다 (BP_GameInstance, 위 필수 설정).
  • 도착 맵은 놓은 캐릭터(또는 PlayerStart) 자리에서 시작합니다. 저장된 체크포인트는 맵 이름이 다르면 무시됩니다. 도착 맵의 첫 체크포인트를 지나야 새로 저장됩니다.

⑤ 확인: Play → 조작이 되는지, 시작 위치·방향이 맞는지, 1~4 키가 GameMode대로 동작하는지 봅니다. 이상하면 아래 표를 보세요.
