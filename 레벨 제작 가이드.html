레벨 제작 가이드

RGB 손전등으로 블록을 비춰 능력을 발동시키고, 버튼·발판·문을 연결해 퍼즐을 만드는 게임입니다. 이 문서는 레벨에 블루프린트를 배치하고 Details 패널에서 설정하는 방법을 설명합니다.

스테이지 흐름: 맵에서 손전등·색 필터를 주움(줍기) → 퍼즐을 풀며 진행 → 통로의 트리거로 다음 맵으로 이동(트리거). 맵 끝에서 가진 필터를 테이블에 반납하면 출구가 열림(반납 테이블).

읽는 법: 표의 변수는 레벨에 배치한 인스턴스의 Details 패널에서 바꿀 수 있는 값입니다. Details 패널에 보이지 않는 변수는 내부 계산용이라 건드릴 필요가 없습니다. 각 장 끝에 "이렇게 만들 수 있어요" 예시가 있습니다.

  • 감지 범위가 원이 아니라 터렛 정면 기준 부채꼴입니다(DetectAngle 기본 150°, 360이면 원).

  • 리스폰 연출: 맞는 순간 0.3초만 세상이 멈추고, 이후 암전 동안은 플레이어만 조작이 막힙니다(레벨 제작에서 할 일 없음).

0기본 개념: 신호 연결

퍼즐 장치는 보내는 쪽(송신)과 받는 쪽(수신)으로 나뉩니다.

역할BP하는 일
송신BP_Button, BP_PressurePlate, BP_Trigger, BP_Pickup, BP_FilterReturnActivate(켜짐) / Deactivate(꺼짐) 신호를 보냄
수신BP_Door, BP_Door2, BP_Light, BP_Light2, BP_AvilityBlock, BP_Hatch신호를 받아 열림 / 켜짐 / 이동 등 반응
연결하는 방법
  1. 레벨에서 송신 장치(버튼, 발판, 트리거, 줍기 아이템, 반납 테이블)를 선택합니다.
  2. Details의 SignalTargets 배열에서 + 를 눌러 칸을 추가합니다. (BP_Trigger만 이름이 Targets입니다.)
  3. 칸을 펼쳐 Target 옆 스포이드 아이콘을 누르고, 뷰포트에서 수신 장치(문, 다락문, 광원, 블록)를 클릭합니다.
  4. Channel에 몇 번 채널로 보낼지 적습니다. 보통은 0(그 장치의 기본 기능) 그대로 두면 됩니다.
  5. 여러 장치를 동시에 움직이려면 칸을 여러 개 추가하면 됩니다.
채널
  • 수신 장치는 기능마다 채널 번호가 정해져 있습니다(장치 BP에 고정, 레벨에서 바꾸지 않음). 0번은 항상 그 장치의 기본 기능입니다. 어떤 기능을 켤지는 송신 장치의 Channel로 고릅니다.
  • 채널 번호는 받는 장치 안에서만 의미가 있습니다. 문의 1번과 광원의 1번은 서로 다른 기능일 수 있습니다.
  • 송신 장치 2개를 같은 수신 장치의 다른 채널로 연결하면, 각각 다른 기능을 켜고 둘 다 켜면 두 기능이 함께 동작합니다.
  • 같은 장치를 다른 채널로 두 칸 넣으면, 버튼 하나로 그 장치의 기능 두 개를 동시에 켤 수 있습니다.
  • 채널마다 신호를 따로 셉니다. 1번 채널 신호는 0번 기능에 영향을 주지 않습니다.

장치별 Channel → 기능 표는 신호 채널 한눈에 보기에 있습니다.

예: 발판 → 광원 Channel 0 + ReOn 버튼 → 같은 광원 Channel 1 = 발판을 밟아 불을 켜 두고, 버튼으로 색을 고르는 퍼즐

SignalTargets 알아둘 점
  • 스포이드 대신 칸의 드롭다운에서 레벨에 있는 액터 이름을 골라도 됩니다.
  • 반응하는 것은 신호를 받을 수 있는 장치(문, 다락문, 맵 광원, 능력 블록)뿐입니다. 벽이나 일반 메시를 넣으면 오류 없이 그냥 무시됩니다.
  • 빈 칸(None)이 있어도 문제는 없지만, 헷갈리지 않게 지워 두는 것이 좋습니다.
  • SignalTargets가 비어 있으면 버튼을 누르거나 발판을 밟아도 아무 일도 일어나지 않습니다.
  • 신호는 상태가 바뀔 때만 보냅니다. 예를 들어 발판에 두 번째 물체가 올라가도 이미 켜져 있으면 신호를 다시 보내지 않습니다.
  • 수신 장치를 복제(Alt+드래그, Ctrl+D)해도 SignalTargets에는 자동으로 추가되지 않습니다. 새 장치는 직접 넣어야 합니다.
ChannelRequired: 신호가 몇 개 모여야 켜지나

모든 수신 장치에 공통으로 있는 설정입니다.

변수설명기본값
ChannelRequired채널별 필요 신호 수 (키 = 채널 번호, 값 = 개수). 이 수 이상 모이면 켜지고, 아래로 떨어지면 꺼짐장치가 받는 채널마다 1 (문 0, 1 → 1, 다락문/블록 0 → 1, 광원 0~4 → 1)
  • 값 1 → 연결된 송신 장치 중 하나만 켜져도 동작 (OR)
  • 값 2 → 두 개가 동시에 켜져야 동작 (AND)
  • 예: 광원 ChannelRequired의 1 → 2 → 전원(0번)은 신호 1개, 색 변경(1번)은 신호 2개가 필요
  • 목록에 없는 채널은 1로 처리됩니다. 값이 0 이하여도 1로 처리됩니다.
  • +를 누르면 0 → 0 칸이 생깁니다. Map은 같은 키를 두 번 가질 수 없으므로, 새 칸을 넣기 전에 기존 칸의 키를 다른 번호로 바꿔 두세요.
  • 여러 송신 장치가 같은 수신 장치의 같은 채널로 보내면 신호가 합산됩니다.
버튼과 발판을 한 장치에 같이 연결하기

버튼과 발판은 같은 신호를 보내므로, 둘 다 같은 수신 장치(같은 채널)를 SignalTargets에 넣을 수 있습니다. 종류를 섞어도 똑같이 합산됩니다.

  • 문(ChannelRequired 0 → 1) + 버튼 + 발판 → 버튼을 누르거나 발판을 밟거나, 둘 중 하나만 해도 열림 (OR)
  • 문(ChannelRequired 0 → 2) + 버튼(Togle) + 발판 → 버튼을 켜 두고 발판에 블록을 올려야 열림 (AND)
  • 문(ChannelRequired 0 → 2) + 버튼(Timed) + 발판 → 발판을 밟은 채 제한 시간 안에 버튼까지 눌러야 열림

AND 조건에 버튼을 쓸 때는 JustOn / Togle / Timed처럼 켜진 상태가 유지되는 모드를 쓰세요. ReOn은 즉시 꺼지므로 발판과 동시에 켜진 상태가 되지 않습니다.

3-2BP_Respawn — 블록·플레이어 되돌리기 구역 구역
흐르는 이미지 (2026-11-08): 구역 벽면에 하늘색 줄무늬가 두 방향으로 흐르는 판(Area, 머티리얼 M_RespawnFlow)이 붙어 있습니다. 디테일의 VisibleArea를 끄면 이미지만 숨겨지고 리스폰은 그대로 동작합니다. 크기는 액터 Scale로만 바꾸세요(판 컴포넌트를 따로 돌리거나 늘리면 어긋납니다). 줄 굵기·속도·밝기는 머티리얼 인스턴스의 Tiling·SpeedU·Intensity로 조절합니다.

보이지 않는 박스입니다. 들어온 Physics 블록은 게임 시작 때 위치로 되돌리고, 들어온 플레이어는 지정한 위치로 소환합니다. 둘 중 무엇을 할지는 구역마다 고릅니다. 신호와는 상관없습니다.

흰 손전등은 색을 더하지 않아서 다른 빛의 색을 바꾸지 않습니다 (빨강 + 흰 빛 = 빨강). 흰 빛만 비추면 All에서만 켜집니다.

이렇게 만들 수 있어요
  • 빛 자물쇠: 센서 UseColor Red → 문 Channel 0 → 빨강으로 1초 비추면 열리고, 빛을 치우면 닫힘
  • 색 섞기 퍼즐: 센서 UseColor Purple + 빨강 맵 광원 → 플레이어가 파랑 손전등을 더해야 열림
  • 거울 퍼즐: 손전등이 직접 닿지 않는 곳의 센서를 거울로 반사해 비추기
  • AND 퍼즐: 센서 2개 → 문 ChannelRequired 0→2 → 두 센서를 동시에 비춰야 열림 (광원 + 손전등 등)

맵 광원은 플레이어가 가까이(PlayerRange 8000 안) 있을 때만 판정합니다. 멀리서는 맵 광원이 센서를 비춰도 켜지지 않습니다.

3-8BP_VoiceTrigger — 음성·자막 구역 구역

플레이어가 이 구역에 들어가면 음성이 나오고 화면 아래에 자막이 뜹니다. 대사와 음성은 구역이 아니라 데이터 테이블 Content/Data/DT_Voice에 모아 두고, 구역에는 재생할 대사의 행 이름만 적습니다. 신호와는 상관없습니다.

1. 대사 적기 — DT_Voice

행 하나 = 자막 한 장입니다. 행 이름이 대사 ID이며, 맵 이름 + 번호로 지으면 어느 구간 대사인지 바로 알 수 있습니다(예: Red_Intro_01).

칸설명기본값

Duration이 자막을 보여 줄 시간(초). 0이면 음성 길이만큼 보여 줍니다. 음성도 없고 0이면 3초0

음성 길이에 맞춰 자막을 보여 주면 되는 보통 대사는 Duration을 0으로 두면 됩니다.

2. 긴 음성 하나에 자막 여러 장

음성 파일을 자르지 않고, 소리는 첫 행에만 넣고 나머지 행은 자막만 적습니다. 다음 행으로 넘어가도 앞 음성은 끊기지 않고 계속 재생됩니다.

  • 각 Duration은 음성을 들으며 그 문장이 끝나는 시간을 재서 넣습니다. 모두 더한 값이 음성 길이와 비슷하면 맞습니다.

  • 구역마다 한 번만 재생합니다. 다시 지나가도 반복하지 않습니다.
  • 재생 기록은 저장하지 않습니다. 게임을 껐다 켜거나 맵을 다시 열면(ESC 메뉴 → 스테이지 초기화 포함) 다시 들립니다. 리스폰은 맵을 다시 여는 것이 아니라서 다시 재생되지 않습니다.

  • 소리 크기는 설정 창의 소리 크기 슬라이더를 따릅니다(따로 설정할 것 없음).

4BP_Door / BP_Door2 — 문 수신

신호를 받으면 좌우로 벌어지며 열리는 미닫이 문입니다.

BP_Door2는 외형(메시)만 다른 문입니다. 설정, 채널, 동작은 BP_Door와 똑같습니다.

설정
변수설명기본값
ChannelRequired채널별 필요 신호 수 (0번 = 열기, 1번 = 강제 닫기). 2 이상이면 AND0 → 1, 1 → 1

상황결과
1번 신호가 켜짐문이 닫히고 영구히 잠김 (열려 있었으면 닫히는 동작, 이미 닫혀 있으면 그대로)
잠긴 뒤 0번(열기) 신호가 켜짐열리지 않음
잠긴 뒤 1번 신호가 꺼짐풀리지 않음 (계속 잠김)
StartOpen 문을 잠금닫힌 채로 유지

설정 방법

  1. 문을 잠글 송신 장치(통과 트리거, 버튼, 줍기 아이템 등)를 선택합니다.
  2. SignalTargets(트리거는 Targets)에 칸을 추가하고, Target = 그 문, Channel = 1로 적습니다.
  3. 같은 송신 장치에 다른 칸을 더 넣으면, 한 번에 "다음 문 열기(Channel 0) + 지나온 문 강제 닫기(Channel 1)"를 함께 할 수 있습니다.
  • 한 번 잠긴 문은 그 판에서 다시 열 방법이 없습니다. 레벨을 다시 시작하면 처음 상태로 돌아옵니다.
  • 1번 신호에는 "꺼짐"이 의미가 없으므로, 한 번 켜고 끝나는 송신 장치(통과 트리거, 줍기 아이템, JustOn 버튼)와 함께 쓰는 것이 자연스럽습니다.
이렇게 만들 수 있어요
  • 타임어택 문: Timed 버튼 연결 → 버튼을 누르고 제한 시간 안에 통과
  • AND 문: 버튼 1개 + 발판 1개를 모두 연결하고 ChannelRequired의 0 → 2
  • 되돌아갈 수 없는 문: 버튼 → 문 Channel 0 (열기) + 문을 지난 곳의 BP_Trigger → 같은 문 Channel 1 (강제 닫기, 3-1 참고)
  • 아이템을 주우면 갇힘: 방 안 BP_Pickup의 SignalTargets에 들어온 문 Channel 1 → 손전등을 줍는 순간 입구가 닫힘
5BP_Light / BP_Light2 — 맵 광원 수신

레벨에 배치하는 광원입니다. 비추는 블록에 색을 더해 줍니다. 수신 장치이기도 해서 버튼·발판·트리거 신호로 켜고 끄기(0), 색 바꾸기(1), 헤드 위아래(2), 좌우 회전(3), 이동(4)을 할 수 있습니다.

맵 광원만으로도 블록 능력이 발동합니다. 손전등과 같이 비추면 두 빛의 색이 합쳐집니다. 예: 맵 광원 빨강 + 손전등 파랑 = 보라.
단, 플레이어가 PlayerRange(8000) 밖에 있으면 맵 광원은 판정을 하지 않으므로 멀리 있는 블록은 플레이어가 다가가야 발동합니다.

빛 범위(굵기) 바꾸는 법

  1. 레벨에서 광원(BP_Light / BP_Light2)을 선택합니다.
  2. Details 패널 위쪽 컴포넌트 목록에서 SpotLight를 클릭합니다.
  3. Light 항목의 Outer Cone Angle을 바꿉니다. 클수록 넓게 퍼집니다. (가장자리를 부드럽게 하는 Inner Cone Angle은 Outer보다 작게 둡니다)
  4. 빛이 닿는 거리는 광원 액터의 LightLength로 바꿉니다. 같은 각도라도 멀리 갈수록 빛 원이 커집니다.

판정용 감지 박스와 원뿔 계산은 이 두 값으로 자동 계산되므로 따로 맞출 것이 없습니다.

BP_BlinkLight · Channel 7신호로 반복 점멸 또는 한 번 점등

BP_Light를 상속한 반복 점멸 광원입니다. 콘텐츠 브라우저의 Content/BluePrint/BP_BlinkLight를 레벨에 배치합니다. 색·빛 길이·회전·이동 설정은 기존 광원과 같습니다.

기둥과 같은 속도로 이동: 이 자식 광원의 이동 트랙은 Linear이므로 MoveSpeed에 지정한 cm/s로 일정하게 움직입니다. 4번 신호를 사용하고, 기둥의 이동 거리와 광원의 MoveOffset, 양쪽 MoveSpeed를 같게 맞추세요. 예를 들어 450cm와 속도 200이면 약 2.25초입니다. 기둥의 첫 경유지 처리로 한 프레임 정도의 출발 차이는 남을 수 있습니다. 점등용 BlinkStartDelay는 이동을 지연시키지 않습니다. 부모 BP_Light의 기존 이동 곡선에는 영향을 주지 않습니다.

  1. BP_BlinkLight를 배치하고 두 시간을 설정합니다. 기본적으로 꺼진 채 신호를 기다립니다.
  2. 기존 BP_Trigger의 Targets 배열에 항목을 추가합니다. Target은 이 광원, Channel은 7, NextLevel은 비웁니다.
  3. 플레이어가 트리거에 들어오면 Blink Start Delay만큼 기다렸다가 켜짐 시간 → 꺼짐 시간 → 켜짐 시간…을 반복합니다. 예: 지연 2 / 켜짐 3 / 꺼짐 2면 처음 2초 대기 후, 3초 켜짐·2초 꺼짐을 계속 반복합니다. 시작 지연은 처음 한 번만 적용됩니다.

반복 모드(Repeat Blink 켜짐): 7번 신호가 꺼지면 지연 또는 반복을 중지하고 소등합니다. 다시 켜면 시작 지연부터 새로 기다립니다. 트리거는 켜짐 신호만 보내므로 통과 후 계속 반복하며, Togle 버튼은 반복 시작·중지 스위치로 사용할 수 있습니다. 발판은 밟는 동안 반복합니다. 이 모드에서 ReOn은 신호가 바로 꺼져 반복도 즉시 중지됩니다.

한 번만 켜고 다시 신호 기다리기: Repeat Blink를 끄고 Blink On Time에 켜 둘 초를 입력합니다. 예: On Time=3, Start Delay=0이면 7번 입력 → 3초 점등 → 자동 소등입니다. Blink Off Time은 사용하지 않습니다. Start Delay를 설정하면 매 새 입력마다 그만큼 기다리고 점등합니다.

매번 다시 누르는 버튼: BP_Button → ButtonMode=ReOn, SignalTargets → Target=이 광원 / Channel=7로 설정합니다. 버튼의 짧은 신호가 끝나도 예약한 한 번 점등은 유지됩니다. BP_BlockSignalTrigger의 ReOn 또는 RepeatOn도 사용할 수 있습니다. 지연/점등 중 재입력은 무시하며 기존 만료 시각을 미루지 않습니다.

단발 모드에서는 신호를 계속 유지해도 한 번 켜진 뒤 자동으로 꺼지고 대기합니다. 재작동에는 새로운 신호 활성화가 필요하므로, 발판은 떼었다 다시 밟고 유지형 버튼은 껐다 다시 켜세요. 기존 BP_Trigger는 기본적으로 한 번만 발동하므로 같은 장치로 여러 번 점등하려면 재입력 가능한 버튼이나 블록 신호 구역을 사용합니다. 단발 모드에서 7번 해제는 점등을 중간 취소하지 않습니다.

각 광원의 시간을 따로 설정할 수 있습니다. 0.01초 미만은 0.01초로 보정합니다. 점멸 중 전원은 7번으로 제어하세요. 0번 전원을 함께 제어하면 다음 점멸 단계가 전원을 다시 바꿉니다. 기존 0~4번 기능은 상속되며, 5·6번에는 연결된 동작이 없습니다.

판정 방식 (알아두면 좋은 것)
  • 빛 원뿔 안의 블록마다 중심 + 꼭짓점 8곳으로 직접 검사합니다. 먼 거리의 작은 블록도 놓치지 않습니다.
  • 벽에 완전히 가려진 블록은 비춰지지 않고, 반쯤 가려진 블록은 비춰집니다.
  • 광원이 꺼져 있거나, 플레이어가 멀거나, 범위 안에 블록이 없으면 검사를 아예 하지 않습니다. 광원을 많이 배치해도 괜찮습니다.
이렇게 만들 수 있어요
  • 색 섞기 퍼즐: 빨강 맵 광원이 비추는 블록에 손전등 파랑을 더해 보라(통과) 능력 발동
  • 스위치 조명: StartOn 끔 + Togle 버튼(Channel 0) → 버튼으로 조명을 켜야 색 조합이 완성됨
  • 발판 조명: StartOn 끔 + 발판(Channel 0) → 블록을 발판에 올려둬야 불이 켜짐
  • 끄는 스위치: StartOn 켬 + Togle 버튼(Channel 0) → 버튼으로 조명을 꺼야 블록 능력이 멈춤
  • 색 회전 퍼즐: ChangeColor = Rotate + ReOn 버튼(Channel 1) → 원하는 색이 될 때까지 버튼을 누름
  • 일시 변색: ChangeColor = Green + Timed 버튼(Channel 1) → 몇 초 동안만 초록으로 바뀜
  • 조명 돌리기: YawAngle = 90 + Togle 버튼(Channel 3) → 버튼으로 빛을 다른 블록 쪽으로 돌림
  • 따라오는 조명: MoveOffset 설정 + 발판(Channel 4) → 발판을 밟는 동안 조명이 다른 자리로 옮겨 감
5-1BP_Mirror — 거울

빛을 받아 반사 빔으로 튕겨 내는 거울입니다. 손전등, 맵 광원, 다른 거울의 빔을 모두 반사합니다. 반사 빔에 맞은 블록은 그 빛의 색으로 능력이 발동합니다.

배치
  • 앞면 = 액터의 초록 화살표(Y) 방향입니다. 앞면으로 들어온 빛만 반사하고, 뒷면은 빛을 막기만 합니다.
  • 거울판 크기는 Scale로 조절합니다: X = 가로, Z = 세로, Y = 두께. 반사 빔의 굵기 = 거울판 크기 그대로입니다 (판 모양 그대로의 사각 기둥).
  • 방향은 액터를 돌려서 맞춥니다.
  • 설정 변수는 없습니다. 빔 길이(3000)는 BP 내부 고정값입니다.
반사 규칙
  • 정면 기준 60° 안으로 들어온 빛만 반사합니다. 너무 비스듬히 스치는 빛은 반사하지 않습니다.
  • 반사 방향은 거울에 들어온 각도 그대로 꺾입니다 (입사각 = 반사각).
  • 빛마다 빔이 따로 나갑니다. 손전등과 맵 광원이 함께 비추면 각자 들어온 방향에 맞게 두 갈래로 반사됩니다. 한 거울에서 최대 3개까지입니다.
  • 빔 색 = 그 빛의 색. 흰 손전등 빛은 흰 빔으로 보이며, 블록에는 흰 빛 규칙 그대로 전달됩니다 (색을 더하지 않고 OwnColor 고유색만 발동).
  • 두 빔이 겹치는 곳은 안개 속에서 섞인 색으로 보입니다 (빨강 + 초록 → 노랑). 보이는 것만 그렇고, 블록 판정은 각 빔의 색 그대로입니다.
  • 한 블록에 빔 여러 개가 닿으면 색이 합쳐집니다 (빨강 빔 + 파랑 빔 = 보라).
  • 빔이 벽이나 물체에 가려지면 그 뒤로는 닿지 않습니다. 거울판 일부만 가려지면 남은 부분으로 나간 빛은 닿습니다.
거울에서 거울로
  • 반사 빔이 다른 거울의 앞면에 닿으면 다시 반사됩니다 (연쇄 반사).
  • 두 거울이 서로 마주 보고 있어도 빛이 무한히 오가지 않습니다. 나를 비추는 거울에는 내가 다시 빛을 보내지 않습니다.
  • 거울 3개 이상을 삼각형처럼 서로 이어지게 배치하는 것은 피하세요. 광원을 꺼도 빛이 남아 있을 수 있습니다 (아직 막지 않음).
알아둘 점
  • 빔은 레벨에 Volumetric Fog(안개)가 있어야 눈에 보입니다. 안개가 없어도 판정은 정상입니다.
  • 빨강·파랑 능력의 기준은 거울입니다 (거울 위치에서 밀려남, 거울 쪽으로 끌려옴). 플레이어 손전등이 함께 비추면 플레이어가 우선입니다.
  • 회전·이동 신호는 없습니다. 방향과 위치는 배치할 때 액터를 돌리고 옮겨서 정합니다.
이렇게 만들 수 있어요

기존 0번 압력판 모드: 플랫폼을 선택하고 디테일 Return Platform → ReturnOnSignalOff를 켭니다. BP_PressurePlate의 SignalTargets에 Target = 플랫폼, Channel = 0을 설정하면 밟을 때 전진하고 떼면 복귀합니다. 복귀도 각 구간의 MovePointSpeeds를 사용하며, 미지정 구간은 MoveSpeed로 이동합니다. 이동 중에도 순간이동 없이 돌아옵니다. 신호를 여러 장치에서 보내면 ChannelRequired의 필요 개수 아래로 내려갈 때 복귀합니다. 위쪽 0번으로 밟는 동안 올라가는 구성은 위의 새 5번 모드를 사용합니다.

귀환 중 다시 밟아도 전진으로 전환하지 않습니다. 시작점에 도착한 뒤 발판을 떼고 다시 밟으면 재출발합니다. 기존 RepeatOn 버튼 + 별도 3번 복귀 구성을 쓸 때는 이 옵션을 꺼 두세요. RepeatOn은 재입력 때 해제·활성화를 연속으로 보내므로 옵션이 켜져 있으면 그 해제가 복귀 명령이 됩니다.

StartDelay는 시작점에서 정방향으로 출발하기 전의 대기입니다. 경유지 사이에는 추가 대기가 없고, 이동 후 복귀 신호를 받으면 바로 귀환을 시작합니다. 지연 중 출발 입력을 반복해도 만료 시각은 미뤄지지 않습니다. 초록빛으로 정지한 동안에도 지연 시간은 흐르지만, 시간이 끝나도 초록 정지가 풀릴 때까지 실제로 움직이지 않습니다.

Move·WaitTrigger·StartMoving은 이 전용 BP가 게임 시작 때 자동으로 설정합니다. 경로·속도·메시를 설정하면 됩니다. 초록 정지는 왕복 중에도 적용됩니다. 이 BP는 0번 출발·3번 귀환·4번 정지·5번 유지형 귀환을 사용하며 기존 1번 순간이동·2번 방향 반전 신호는 처리하지 않습니다.

플랫폼 설정: ReturnOnSignalOff=false로 두고 MovePoint·MoveSpeed·MovePointSpeeds·StartDelay는 원하는 값으로 사용합니다. 블록 접촉 정지가 필요 없는 이 장면에서는 StopOnAbilityBlockContact=false를 사용하세요. 플랫폼 하나당 제어 BP 하나만 연결합니다.

  • 시작점 발판과 스위치가 모두 켜지면 건너편으로 출발합니다. 이동 중 또는 건너편 도착 후 하나라도 꺼지면 중간에 정지하지 않고 MovePoint[0]으로 돌아옵니다. 발판에서 큐브를 치워도 시작점으로 복귀합니다. 복귀 도중 조건이 다시 켜져도 우선 시작점까지 돌아온 뒤 대기합니다.
  • 건너편 ReOn 버튼은 이동 중에도 즉시 작동합니다. 건너편으로 가는 중이거나 건너편에 도착해 있으면 시작점으로 보내고, 시작점에 있거나 시작점으로 돌아오는 중이면 건너편으로 부릅니다. 누를 때마다 현재 목적지가 반대로 바뀝니다.
  • 출발 지연 중 건너편 버튼을 누르면 예약을 취소하고 시작점에서 대기합니다. 다시 누르면 독립적으로 건너편 출발을 요청합니다. 순간이동하거나 입력을 예약하지 않습니다. 초록빛 정지는 유지하되 목적지 변경은 받아 두므로 초록빛이 해제되면 마지막 요청 방향으로 움직입니다.
  • 건너편 버튼으로 왕복 중에는 시작점 두 입력이 없어도 계속 움직입니다. 도착하면 대기하며, 이미 켜져 있던 시작점 입력 때문에 자동으로 다시 출발하지 않습니다. 시작점에서 다시 보내려면 입력 하나를 껐다 켜 두 조건을 새로 충족시키세요.
  • 출발 지연 중 조건이 끊기면 예약이 취소됩니다. 다시 충족되면 StartDelay 전체부터 기다립니다. 회전·스케일·메시·초록 정지·구간 속도는 기존 플랫폼 설정을 따릅니다.
MovePoint 설정 방법

Move가 Patrol 계열일 때 블록이 지나갈 경유지 목록입니다.

  1. 블록을 선택하고 Details의 MovePoint 배열에서 + 를 눌러 경유지를 추가합니다.
  2. 뷰포트에 경유지마다 작은 다이아몬드 모양 위젯이 나타납니다. 이것을 끌어서 위치를 잡습니다. (Details에서 X/Y/Z 숫자를 직접 입력해도 됩니다.)
  3. 블록은 배열 순서(0 → 1 → 2 …)대로 이동합니다. 순서를 바꾸려면 배열 칸을 위아래로 옮기세요.
  • 좌표는 블록 기준 상대 위치입니다. (0, 0, 300)은 "블록에서 위로 300". 그래서 블록을 옮기면 경로도 같이 따라 움직입니다.
  • 블록을 회전하거나 크기를 바꾸면 경로도 같이 회전·확대됩니다. 게임 시작 시 한 번 월드 좌표로 바꿔 두기 때문에, 이동 중에는 경로가 블록을 따라가지 않습니다.
  • 속도는 MoveSpeed(초당 이동 거리)로 일정하게 움직입니다. 경유지 사이가 멀수록 오래 걸립니다.
  • Move가 Fixed나 Physics면 MovePoint는 무시됩니다.

시간차 낙하·플레이어 밀기 BP_FallingHazardBlock

매번 신호를 받아야 다시 스폰하기: 낙하 블록을 선택하고 Fall Cycle → Require Signal Each Fall을 켭니다. 기본값은 꺼짐입니다.

  1. 켜면 게임 시작부터 신호를 기다립니다. 0번 신호를 받으면 StartDelay 후 한 번 낙하합니다.
  2. 아래 BP_Respawn의 ResetBlock=true 영역에 닿으면 원래 위치로 돌아와 다음 신호를 기다립니다. HideWhileWaiting=true이면 대기 중 숨겨집니다.
  3. 다음 0번 신호를 받아야 다시 낙하합니다. BP_Button 또는 BP_BlockSignalTrigger의 ReOn 모드에 Target=이 블록, Channel=0을 연결하면 매 입력마다 다시 사용할 수 있습니다.
  4. 옵션을 끄면 기존 자동 시작·첫 신호 시작·반복 및 공통 시간표 설정을 따릅니다. 이 옵션은 블록 인스턴스마다 따로 켜고 끌 수 있습니다.

이 모드에서는 WaitForStartSignal 값과 무관하게 첫 신호가 필요하고, RepeatFalls / RepeatInterval / UseSharedSchedule 대신 신호마다 StartDelay를 사용합니다. 공중 입력은 다음 낙하로 쌓이지 않으며 지연 중 중복 입력도 시간을 늘리지 않습니다. 압력판 등 신호가 계속 켜져 있는 장치는 해제 후 다시 켜져야 재출발합니다. 기본 BP_Trigger는 한 번만 송신하므로 반복 출발에는 반복 입력 장치를 사용하세요. 3번 정지와 초록빛 정지는 기존처럼 우선합니다.

트리거를 밟아야 낙하 시작하기: 낙하 블록의 Fall Cycle → Wait For Start Signal을 켭니다. 기존 BP_Trigger의 Targets 배열에 항목을 추가해 Target을 이 블록, Channel을 0으로 설정하고 NextLevel은 비워 둡니다. 플레이어가 구역에 들어오면 StartDelay 후 출발합니다. 여러 블록을 하나의 트리거에 넣으면 같은 신호를 받아 각자 지연 후 떨어집니다.

블록 진입용 BP_BlockSignalTrigger를 쓴다면 배열 이름은 SignalTargets입니다. 버튼도 Target/Channel 0으로 사용할 수 있으며 짧은 ReOn 신호도 됩니다. 기존 최초 시작 모드(RequireSignalEachFall=false)는 한 번 시작하면 리스폰 후 자동 반복하고, 반복 신호나 신호 꺼짐으로 출발 시간이 바뀌지 않습니다. 매번 신호가 필요한 경우 위의 새 옵션을 켜세요. 기존 WaitTrigger / StartMoving은 Patrol용입니다.

공통 시간표로 묶음 간격 유지하기: 같은 시계를 기준으로 자기 차례에만 출발합니다. 초록빛으로 멈추거나 리스폰이 늦어 차례를 놓치면 그 회차는 건너뛰고 다음 자기 차례까지 기다립니다.

정지·복귀: 3번이 켜진 동안도 시계는 계속 갑니다. 해제 후에는 다음 자기 차례를 기다립니다. 예를 들어 1묶음이 9초에 준비되지 못했다면 11초에 준비되어도 바로 출발하지 않고 18초 차례를 기다립니다. 그때도 준비되지 않았다면 다음 회차를 건너뜁니다. 공중에서 초록빛이 풀린 블록은 기존처럼 그 자리에서 낙하를 이어갑니다. 이것은 새로운 출발과 별개입니다.

3번 신호로 다음 낙하 정지: 신호를 보내는 장치의 대상에 이 낙하 블록을 넣고 Channel = 3으로 설정합니다. 별도의 활성화 옵션은 필요 없습니다.

  • 신호 켜짐: 출발 대기 시간을 멈춥니다. 이미 떨어지고 있는 블록은 계속 낙하하고, 기존 BP_Respawn에 닿아 시작 위치로 돌아오면 다음 출발을 대기합니다. 대기 중 표시 여부는 HideWhileWaiting 설정을 따릅니다.
  • 신호 꺼짐: 공통 시간표 사용 시 다음 자기 차례를 기다립니다. 공통 시간표를 끈 개별 모드에서는 정지했을 때 남아 있던 대기 시간부터 이어갑니다. 예를 들어 1초 남았을 때 정지했다면 해제 후 1초 뒤 출발합니다. 정지 중 0번 시작 신호를 받으면 해제 후 StartDelay 전체를 기다립니다.
  • 영구 정지: 기존 BP_Trigger → Targets에 대상 블록 / 3번을 설정하고 NextLevel은 비웁니다. 트리거는 켜짐만 보내므로 통과 후 다음 낙하가 계속 중단됩니다.
  • 정지·재개 스위치: Togle 버튼은 누를 때마다 정지/재개, 발판은 밟는 동안 정지합니다. 이 장치들의 배열 이름은 SignalTargets입니다. ReOn은 바로 해제되어 지속 정지에는 쓰지 않습니다.

0번은 기존 시작 신호, 3번은 별도 정지 신호입니다. 초록빛으로도 정지 중이면 3번만 해제해도 출발하지 않습니다. RepeatFalls 꺼짐이나 RepeatInterval = 0에서도 정지 신호가 우선합니다. 공중의 블록을 즉시 순간이동시키거나 얼리는 기능은 아닙니다.

UserStaticMesh와 기존 색 능력은 상속됩니다. 단일 플레이어 기준으로 검증했습니다.

6-1BP_GreenGroupStop — 초록빛으로 여러 블록 정지

흰색 받침 하나에 초록빛 능력을 발동시켜 여러 Patrol 기둥을 함께 멈출 때 사용합니다. 받침의 초록 효과가 끝나면 대상들이 다시 움직입니다.

  1. Content/BluePrint/BP_GreenGroupStop을 배치하고 ColorMode = ReactOnly, UseColor = Green으로 설정합니다. 현재 Green 레벨 받침은 Move = PatrolRotation이며 기존 경로를 유지합니다.
  2. 멈출 블록마다 기존 Patrol 모드와 경로를 유지하고 WaitTrigger와 StartMoving을 켭니다. ChannelRequired는 0 → 1입니다.
  3. 받침의 Details에서 Stop Targets를 검색합니다. +로 칸을 추가해 멈출 BP_AvilityBlock을 각각 지정합니다. None인 칸은 무시됩니다.
  4. 플레이 중 받침에 초록빛을 비춰 충전합니다. 효과 발동 시 대상들이 정지하고, 효과가 해제되면 원래 Patrol 이동을 재개합니다. 기존 초록 능력의 충전·유지·쿨타임을 따릅니다.

현재 Green 레벨은 BP_AvilityBlock3이 받침이고, BP_AvilityBlock4~7이 대상입니다. 같은 대상의 0번 채널에 다른 스위치 신호를 섞으면 신호 합산 규칙이 적용됩니다.

흰색 받침이 빛에 반응하지 않으면: 보이는 메시의 충돌이 NoCollision인지 확인합니다. 현재 받침 SM_Floor_Plain_Light에는 Custom → Query Only → Visibility: Block을 적용했습니다. 캐릭터·블록 등 물체 채널은 Ignore라서 물리적으로 막지 않습니다. 모양은 그대로이며 손전등 레이만 받습니다. Fixed나 사용자 메시 설정으로 받침 메시가 없어지면 실제로 보이는 본체 메시 쪽에 Visibility 충돌이 필요합니다.

Patrol 이동 제어용입니다. Physics 블록을 묶어 얼리는 기능은 아닙니다. 이 BP는 원본 블록의 복제본이므로 원본 수정이 자동으로 반영되지는 않습니다. 실제 플레이어 초록 손전등 입력으로 대상 4개 정지, 손전등 끄기 후 재개까지 확인했습니다.

한쪽 모서리를 경첩으로 삼아 90도 회전하며 열리고 닫히는 판입니다. 바닥 뚜껑, 다락문, 들리는 다리 등에 씁니다. 빛이나 색 능력에는 반응하지 않습니다. 능력 블록과는 별개의 장치입니다.

  • CloseAfterFullyOpen 꺼짐: 열리는 도중 신호가 꺼지면 그 각도에서 멈추고 CloseDelay 뒤 닫힙니다. 지연 대기 중 반대 요청은 이전 예약을 취소합니다. 열림 지연이 끝나기 전에 발판을 떼면 열기 예약도 취소합니다.
  • 완전히 열린 경우에만 대기시키기: WaitTrigger와 Close After Fully Open을 켜고 Close Delay에 대기할 초를 입력합니다. 예: Open Time=1.5, Close Delay=1이면 끝까지 열린 뒤 발판을 뗀 순간부터 1초를 기다리고 닫힙니다. 열리는 도중 떼면 즉시 닫히며, OpenDelay 대기 중 떼면 열기 예약을 취소합니다.
  • 발판을 계속 밟으면 열린 채입니다. 완전히 열린 상태로 오래 밟았어도 떼는 순간부터 전체 CloseDelay를 기다립니다. 닫기 대기 중 다시 밟으면 닫기 예약이 취소되고, 다음에 떼면 새 해제 시점부터 전체 지연을 적용합니다. 대기 중 같은 닫기 요청을 반복해도 예약 시간이 미뤄지지 않습니다.
  • 닫히는 도중 열기 요청을 받으면 기존처럼 OpenDelay 뒤 현재 각도에서 열립니다. 다시 완전히 열린 뒤 신호가 끊기면 그 해제 시점부터 다음 닫기 대기 시간을 셉니다. CloseDelay가 0 이하이면 완전히 열렸더라도 추가 대기 없이 닫힙니다.
  • StartOpen은 게임 시작 때 즉시 열린 자세를 설정하고 0번 신호 동작을 반대로 합니다. 이 경우에는 반전된 닫기 요청이 들어온 순간부터 CloseDelay를 적용합니다. 게임 시작 시각이나 완전히 열린 시각에서 세지 않습니다. 열기는 OpenDelay를 사용합니다.
  • 반복형에서는 게임 시작 → OpenDelay → 열림 이동 → HatchWait → CloseDelay → 닫힘 이동 → HatchWait 순서로 반복합니다. 예: OpenDelay=1, CloseDelay=2, OpenTime=1.5이면 열기 전 1초, 닫기 전 2초를 기다리고 각 이동은 1.5초 걸립니다.
