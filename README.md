# GaesinLight 레벨 제작 매뉴얼

RGB 손전등으로 블록을 비춰 능력을 발동시키고, 버튼·발판·문을 연결해 퍼즐을 만드는 게임입니다.
이 문서는 레벨에 블루프린트를 배치하고 Details 패널에서 설정하는 방법을 설명합니다.

> 읽는 법
> - 표의 변수는 레벨에 배치한 인스턴스의 Details 패널에서 바꿀 수 있는 값입니다.
> - Details 패널에 보이지 않는 변수는 내부 계산용이라 건드릴 필요가 없습니다.
> - 각 BP 설명 끝에 "이렇게 만들 수 있어요" 예시가 있습니다.

## 0. 기본 개념: 신호 연결

퍼즐 장치는 보내는 쪽(송신)과 받는 쪽(수신)으로 나뉩니다.

| 역할 | BP | 하는 일 |
|---|---|---|
| 송신 | BP_Button, BP_PressurePlate | `Activate`(켜짐) / `Deactivate`(꺼짐) 신호를 보냄 |
| 수신 | BP_Door, BP_Light, BP_AvilityBlock, BP_Hatch | 신호를 받아 열림 / 켜짐 / 이동 등 반응 |

### 연결하는 방법
1. 레벨에서 송신 장치(버튼, 발판)를 선택합니다.
2. Details의 `SignalTargets` 배열에서 + 를 눌러 칸을 추가합니다.
3. 칸을 펼쳐 `Target` 옆 스포이드 아이콘을 누르고, 뷰포트에서 수신 장치(문, 광원, 블록)를 클릭합니다.
4. `Channel`에 몇 번 채널로 보낼지 적습니다. 보통은 `0`(그 장치의 기본 기능) 그대로 두면 됩니다.
5. 여러 장치를 동시에 움직이려면 칸을 여러 개 추가하면 됩니다.

### 채널
- 수신 장치는 기능마다 채널 번호가 정해져 있습니다(장치 BP에 고정, 레벨에서 바꾸지 않음). 0번은 항상 그 장치의 기본 기능입니다. 어떤 기능을 켤지는 송신 장치의 `Channel`로 고릅니다.
- 채널 번호는 받는 장치 안에서만 의미가 있습니다. 문의 1번과 광원의 1번은 서로 다른 기능일 수 있습니다.
- 송신 장치 2개를 같은 수신 장치의 다른 채널로 연결하면, 각각 다른 기능을 켜고 둘 다 켜면 두 기능이 함께 동작합니다.

#### 채널 번호표 (하려는 기능 → 보낼 채널)
송신 장치의 `Channel`에 아래 번호를 적으면 그 기능이 동작합니다.

| 수신 장치 | 하려는 기능 | Channel | 신호 켜짐 | 신호 꺼짐 |
|---|---|---|---|---|
| 문 | 문 열기 | 0 | 열림 | 닫힘 |
| 다락문 | 다락문 열기 (`WaitTrigger` 켬일 때만) | 0 | 열림 | 닫힘 |
| 능력 블록 | Patrol 이동 출발 (`WaitTrigger` 켬일 때만) | 0 | 출발 | 그 자리에서 정지 |
| 맵 광원 | 전원 켜기/끄기 | 0 | 켜짐 | 꺼짐 |
| 맵 광원 | 색 바꾸기 (`ChangeColor` 설정대로) | 1 | `Red`/`Green`/`Blue`면 그 색, `Rotate`면 빨강→초록→파랑 순서로 다음 색 | 원래 색(`LightColor`)으로 복귀. `Rotate`는 무시 |
| 맵 광원 | (예약: 이동/회전, 작업 4) | 2 | - | - |

- 표에 없는 번호로 보내면 아무 일도 일어나지 않습니다.
- "시작부터 켜진 상태" 설정(문/다락문 `StartOpen`, 능력 블록 `StartMoving`)을 켠 장치는 켜짐/꺼짐이 반대입니다. 예: `StartOpen` 문은 신호가 켜지면 닫히고, 꺼지면 다시 열립니다.
- 예: 발판 → 광원 Channel 0 + `ReOn` 버튼 → 같은 광원 Channel 1 = 발판을 밟아 불을 켜 두고, 버튼으로 색을 고르는 퍼즐

- 같은 장치를 다른 채널로 두 칸 넣으면, 버튼 하나로 그 장치의 기능 두 개를 동시에 켤 수 있습니다.
- 채널마다 신호를 따로 셉니다. 1번 채널 신호는 0번 기능에 영향을 주지 않습니다.

SignalTargets 알아둘 점
- 스포이드 대신 칸의 드롭다운에서 레벨에 있는 액터 이름을 골라도 됩니다.
- 반응하는 것은 신호를 받을 수 있는 장치(문, 맵 광원, 능력 블록)뿐입니다. 벽이나 일반 메시를 넣으면 오류 없이 그냥 무시됩니다.
- 빈 칸(None)이 있어도 문제는 없지만, 헷갈리지 않게 지워 두는 것이 좋습니다.
- SignalTargets가 비어 있으면 버튼을 누르거나 발판을 밟아도 아무 일도 일어나지 않습니다.
- 신호는 상태가 바뀔 때만 보냅니다. 예를 들어 발판에 두 번째 물체가 올라가도 이미 켜져 있으면 신호를 다시 보내지 않습니다.
- 수신 장치를 복제(Alt+드래그, Ctrl+D)해도 SignalTargets에는 자동으로 추가되지 않습니다. 새 장치는 직접 넣어야 합니다.

### ChannelRequired: 신호가 몇 개 모여야 켜지나
모든 수신 장치에 공통으로 있는 설정입니다.

| 변수 | 설명 | 기본값 |
|---|---|---|
| `ChannelRequired` | 채널별 필요 신호 수 (키 = 채널 번호, 값 = 개수). 이 수 이상 모이면 켜지고, 아래로 떨어지면 꺼짐 | 장치가 받는 채널마다 1 (문/다락문/블록 `0 → 1`, 광원 `0~3 → 1`) |

- 값 1 → 연결된 송신 장치 중 하나만 켜져도 동작 (OR)
- 값 2 → 두 개가 동시에 켜져야 동작 (AND)
- 예: 광원 `ChannelRequired`의 `1 → 2` → 전원(0번)은 신호 1개, 색 변경(1번)은 신호 2개가 필요
- 목록에 없는 채널은 1로 처리됩니다. 값이 0 이하여도 1로 처리됩니다.
- +를 누르면 `0 → 0` 칸이 생깁니다. Map은 같은 키를 두 번 가질 수 없으므로, 새 칸을 넣기 전에 기존 칸의 키를 다른 번호로 바꿔 두세요.
- 여러 송신 장치가 같은 수신 장치의 같은 채널로 보내면 신호가 합산됩니다.

### 버튼과 발판을 한 장치에 같이 연결하기
버튼과 발판은 같은 신호를 보내므로, 둘 다 같은 수신 장치(같은 채널)를 SignalTargets에 넣을 수 있습니다. 종류를 섞어도 똑같이 합산됩니다.

- 문(`ChannelRequired` `0 → 1`) + 버튼 + 발판 → 버튼을 누르거나 발판을 밟거나, 둘 중 하나만 해도 열림 (OR)
- 문(`ChannelRequired` `0 → 2`) + 버튼(`Togle`) + 발판 → 버튼을 켜 두고 발판에 블록을 올려야 열림 (AND)
- 문(`ChannelRequired` `0 → 2`) + 버튼(`Timed`) + 발판 → 발판을 밟은 채 제한 시간 안에 버튼까지 눌러야 열림

> AND 조건에 버튼을 쓸 때는 `JustOn` / `Togle` / `Timed`처럼 켜진 상태가 유지되는 모드를 쓰세요. `ReOn`은 즉시 꺼지므로 발판과 동시에 켜진 상태가 되지 않습니다.

## 1. BP_Charactor — 플레이어

손전등을 들고 다니는 플레이어입니다. 레벨에 직접 배치할 경우 Auto Possess Player = Player 0으로 설정하세요. (또는 PlayerStart + GameMode의 Default Pawn Class 사용)

### 조작
| 입력 | 동작 |
|---|---|
| `1` | 손전등 흰색 |
| `2` / `3` / `4` | 손전등 색 전환 (빨강 / 초록 / 파랑) |
| `F` | 바라보는 대상과 상호작용 — 버튼이면 누르기, 블록이면 잡기 / 놓기 |

## 2. BP_Button — 버튼

플레이어가 바라보고 상호작용 키(F)를 누르는 버튼입니다. 송신 장치입니다.

### 설정
| 변수 | 설명 | 기본값 |
|---|---|---|
| `SignalTargets` | 신호를 보낼 수신 장치와 채널 목록 (Target은 스포이드로 지정, Channel 기본 0. 0번 "연결하는 방법" 참고) | 비어 있음 |
| `ButtonMode` | 버튼 동작 방식 (아래 표) | `JustOn` |
| `TimedDuration` | `Timed` 모드에서 켜져 있는 시간(초) | 10 |
| `UseAsset` | 켜면 아래 `UseStaticMesh`로 버튼 외형 교체 | 꺼짐 |
| `UseStaticMesh` | 사용할 버튼 메시 (콜리전이 있는 메시여야 상호작용 가능) | 없음 |

### ButtonMode
| 모드 | 동작 | 어울리는 수신 장치 |
|---|---|---|
| `JustOn` | 한 번 누르면 켜진 채로 고정. 다시 눌러도 변화 없음 | 한 번 열리면 끝나는 문 |
| `Togle` | 누를 때마다 켜짐 ↔ 꺼짐 | 열고 닫을 수 있는 문, 광원 전원(0번) |
| `ReOn` | 누를 때마다 켜짐 → 즉시 꺼짐 신호를 한 번에 보냄 (펄스) | Rotate 광원 (누를 때마다 색 한 칸씩 회전) |
| `Timed` | 누르면 켜지고 `TimedDuration`초 뒤 자동으로 꺼짐 | 시간 제한 문 |


> `ReOn`은 "톡 치는" 신호라서 문에 쓰면 열리자마자 닫힙니다. 누를 때마다 한 번 반응하는 장치 전용입니다. (예 : 라이트 색 변경)

### 이렇게 만들 수 있어요
- `JustOn` + 문: 한 번 열면 계속 열려 있는 출구
- `ReOn` + Rotate 광원: 버튼을 누를 때마다 빛 색이 빨강 → 초록 → 파랑으로 바뀌는 색 맞추기 퍼즐
- `Timed`(5초) + 문: 버튼을 누르고 5초 안에 문을 통과해야 하는 타임어택

## 3. BP_PressurePlate — 발판

무언가 올라가 있는 동안 신호를 보내는 발판입니다. 송신 장치입니다.

### 감지 대상
- 플레이어 (`BP_Charactor`)
- 능력 블록 (`BP_AvilityBlock`)
- 하나라도 올라가 있으면 켜짐, 모두 내려오면 꺼짐

### 설정
| 변수 | 설명 | 기본값 |
|---|---|---|
| `SignalTargets` | 신호를 보낼 수신 장치와 채널 목록 (Target은 스포이드로 지정, Channel 기본 0. 0번 "연결하는 방법" 참고) | 비어 있음 |

### 이렇게 만들 수 있어요
- 발판 + 문: 발판 위에 있는 동안만 문이 열림 → 플레이어가 내려오면 닫힘
- Physics 블록을 발판 위에 올려두기: 블록을 잡아서 발판에 올려두면 문이 계속 열려 있음
- 발판 2개 + 문(`ChannelRequired` `0 → 2`): 두 발판을 동시에 눌러야 열리는 문. 하나는 플레이어, 하나는 블록으로 누르는 퍼즐
- 파란 능력(당기기)으로 블록을 발판까지 끌어오기: 능력과 장치를 섞은 퍼즐

## 4. BP_Door — 문

신호를 받으면 좌우로 벌어지며 열리는 미닫이 문입니다. 수신 장치입니다.

### 설정
| 변수 | 설명 | 기본값 |
|---|---|---|
| `ChannelRequired` | 채널별 필요 신호 수 (0번 = 열기). 2 이상이면 AND | `0 → 1` |
| `StartOpen` | 켜면 열린 채로 시작. 신호가 켜지면 닫히고 꺼지면 다시 열림 (반대 동작). 에디터에서도 열린 모습으로 보임 | 꺼짐 |

- 열리는 거리와 시간은 모든 문이 같은 고정값입니다.
- 신호가 꺼지면 열린 만큼 거꾸로 닫힙니다. 열리는 도중에 꺼져도 자연스럽게 되돌아갑니다.

### 이렇게 만들 수 있어요
- 타임어택 문: `Timed` 버튼 연결 → 버튼을 누르고 제한 시간 안에 통과
- AND 문: 버튼 1개 + 발판 1개를 모두 연결하고 `ChannelRequired`의 `0 → 2`

## 5. BP_Light — 맵 광원

레벨에 고정 배치하는 광원입니다. 비추는 블록에 색을 더해 줍니다. 수신 장치이기도 해서 버튼/발판으로 켜고 끄거나 색을 바꿀 수 있습니다.

> 맵 광원만으로도 블록 능력이 발동합니다. 손전등과 같이 비추면 두 빛의 색이 합쳐집니다. 예: 맵 광원 빨강 + 손전등 파랑 = 보라.
> 단, 플레이어가 `PlayerRange`(8000) 밖에 있으면 맵 광원은 판정을 하지 않으므로 멀리 있는 블록은 플레이어가 다가가야 발동합니다.

### 설정
| 변수 | 설명 | 기본값 |
|---|---|---|
| `ChannelRequired` | 채널별 필요 신호 수 (0 전원, 1 색, 2 이동, 3 회전). 2 이상이면 AND | `0~3 → 1` |
| `LightColor` | 광원의 기본 색 (Red / Blue / Green). 에디터에서 바로 미리보기됨 | `Red` |
| `StartOn` | 켜진 채로 시작. 끄면 꺼진 채 시작 (에디터에서도 빛이 꺼져 보임). 0번 신호는 반대로 동작 (아래 "전원" 표) | 켜짐 |
| `ChangeColor` | 1번 채널 신호를 받았을 때 바꿀 색 (아래 표) | `Rotate` |
| `LightLength` | 빛 판정 거리 | 5000 |


SpotLight 컴포넌트 설정도 판정에 영향을 줍니다.
- Outer Cone Angle: 빛 원뿔 각도 = 판정 범위. 각도를 바꾸면 판정도 자동으로 따라갑니다.

### 전원 (StartOn + 0번 채널)
| 하고 싶은 것 | 설정 |
|---|---|
| 항상 켜진 광원 | `StartOn` 켬, 0번 채널에 아무것도 연결 안 함 |
| 평소 꺼져 있고 신호 동안 켜짐 | `StartOn` 끔 + 송신 장치 Channel 0 |
| 평소 켜져 있고 신호 동안 꺼짐 | `StartOn` 켬 + 송신 장치 Channel 0 |
### ChangeColor
| 값 | 동작 |
|---|---|
| `Red` / `Green` / `Blue` | 신호가 켜지면 그 색으로, 꺼지면 원래 색(`LightColor`)으로 복귀 |
| `Rotate` | 신호가 켜질 때마다 빨강 → 초록 → 파랑 → 빨강 순으로 회전. 꺼짐 신호는 무시 (`ReOn` 버튼과 함께 사용) |

### 판정 방식 (알아두면 좋은 것)
- 빛 원뿔 안의 블록마다 중심 + 꼭짓점 8곳으로 직접 검사합니다. 먼 거리의 작은 블록도 놓치지 않습니다.
- 벽에 완전히 가려진 블록은 비춰지지 않고, 반쯤 가려진 블록은 비춰집니다.
- 광원이 꺼져 있거나, 플레이어가 멀거나, 범위 안에 블록이 없으면 검사를 아예 하지 않습니다. 광원을 많이 배치해도 괜찮습니다.

### 이렇게 만들 수 있어요
- 색 섞기 퍼즐: 빨강 맵 광원이 비추는 블록에 손전등 파랑을 더해 보라(통과) 능력 발동
- 스위치 조명: `StartOn` 끔 + `Togle` 버튼(Channel 0) → 버튼으로 조명을 켜야 색 조합이 완성됨
- 발판 조명: `StartOn` 끔 + 발판(Channel 0) → 블록을 발판에 올려둬야 불이 켜짐
- 끄는 스위치: `StartOn` 켬 + `Togle` 버튼(Channel 0) → 버튼으로 조명을 꺼야 블록 능력이 멈춤
- 색 회전 퍼즐: `ChangeColor = Rotate` + `ReOn` 버튼(Channel 1) → 원하는 색이 될 때까지 버튼을 누름
- 일시 변색: `ChangeColor = Green` + `Timed` 버튼(Channel 1) → 몇 초 동안만 초록으로 바뀜

## 6. BP_AvilityBlock — 능력 블록

빛을 받으면 색이 바뀌고, 그 색의 능력이 발동하는 블록입니다. `ColorMode`로 아무 색에나 반응할지, 특정 색에만 반응할지, 고유 색을 품고 있다가 들어온 빛과 섞을지 고릅니다. 수신 장치이기도 해서, 신호를 받으면 이동을 시작하게 할 수 있습니다. 외형을 바꾸면 움직이는 발판이나 벽으로도 쓸 수 있습니다.

### 6-1. 공통 설정
| 변수 | 설명 | 기본값 |
|---|---|---|
| `ChannelRequired` | 채널별 필요 신호 수 (0번 = `WaitTrigger` 이동 시작/정지). 2 이상이면 AND | `0 → 1` |
| `ColorMode` | 색 반응 방식 (아래 표) | `Default` |
| `UseColor` | `ColorMode`에서 쓰는 색 (All / Red / Blue / Green / Purple / Yello / SkyBlue / None) | `All` |
| `Move` | 이동 방식 (아래 표). 능력 효과도 이 값에 따라 달라짐 | `Fixed` |
| `MovePoint` | Patrol 경유지 목록 (블록 기준 상대 좌표). 뷰포트에서 위젯을 끌어서 편집. 아래 "MovePoint 설정 방법" 참고 | 비어 있음 |
| `MoveSpeed` | Patrol 이동 속도 | 500 |
| `WaitTrigger` | 켜면 신호를 받을 때까지 Patrol을 시작하지 않음. 신호가 꺼지면 그 자리에서 멈춤 | 꺼짐 |
| `StartMoving` | `WaitTrigger` 켬일 때 켜면 반대로 동작: 처음부터 Patrol 이동, 신호가 켜지면 그 자리에서 멈추고 꺼지면 다시 출발 | 꺼짐 |
| `IsUserStaticMesh` | 켜면 아래 메시로 외형 교체 | 꺼짐 |
| `UserStaticMesh` | 사용할 메시 (발판, 벽 등) | 없음 |
| `CanGrab` | 켜면 플레이어가 F로 들고 놓을 수 있음. `Move = Physics`일 때만 적용 | 꺼짐 |
| `CanGrabSkyBlue` | 켜면 SkyBlue 능력으로 작아진 동안 들 수 있음. `CanGrab`이 꺼져 있어 평소엔 못 드는 블록도 작아지면 들 수 있게 됨. 끄면 작아져도 못 듦 | 켜짐 |

### 들기 (CanGrab)
- 들 수 있는 조건: `Move = Physics` + `CanGrab` 켜짐. 바라보면 상호작용 문구가 뜨고 F로 들기 / 놓기.
- 든 블록은 플레이어가 보는 방향을 따라 돌고, 잡는 순간 수평·정면으로 정렬됩니다 (위아래를 봐도 기울지 않음).
- 능력이 발동한 동안은 색에 따라 들기가 막힙니다. 들고 있는 중에 막히는 능력이 발동하면 자동으로 손에서 놓습니다.

| 능력 | 발동 중 들기 |
|---|---|
| Red / Blue | 가능 (그대로) |
| Green (정지) | 불가 |
| Yello (커짐) | 불가 |
| Purple (반투명) | 불가 |
| SkyBlue (작아짐) | `CanGrabSkyBlue`를 따름 (`CanGrab`이 꺼져 있어도 켜져 있으면 가능) |

- 예: 평소엔 못 드는 큰 상자(`CanGrab` 끔, `CanGrabSkyBlue` 켬, `Physics`) → 하늘색으로 작게 만들어야 들고 옮길 수 있음.

### ColorMode
| 값 | 동작 | 크리스탈 색 | 기본 메시 |
|---|---|---|---|
| `Default` | 비춰진 색 그대로 능력 발동. `UseColor` 무시 | 흰색 | `SM_Element_Plain` |
| `ReactOnly` | 비춰진 색(섞인 결과)이 `UseColor`와 같을 때만 발동. `UseColor = All`이면 아무 색이나 | `UseColor`의 연한 색 | `SM_Element_Chain` |
| `OwnColor` | 블록이 `UseColor`를 품고 있음. 빛이 들어오면 그 빛과 합친 색으로 발동 (예: 고유 Red + 파랑 빛 = Purple). 빛이 없으면 아무것도 안 함 | `UseColor`의 진한 색 | `SM_Element_Chain` |

- 색 합치기는 빛의 삼원색(R/G/B)을 더하는 방식입니다. 고유색과 들어온 빛에 같은 성분이 있으면 한 번만 셉니다 (고유 Red + 빨강 빛 = Red).
- `OwnColor`에 섞인 색도 넣을 수 있습니다. 고유 Yello(R+G) + 파랑 빛 = R+G+B → 흰색이라 능력이 없습니다.
- `OwnColor`에서 `UseColor`가 `All`이나 `None`이면 고유색이 없는 것과 같아 `Default`처럼 동작합니다.
- 예전 `ReactColor`로 특정 색을 지정해 두었던 블록은 `ColorMode = ReactOnly` + `UseColor`를 같은 색으로 맞추세요.
- `IsUserStaticMesh`를 켜면 메시는 `UserStaticMesh`로 바뀌고 크리스탈 색 칠하기는 건너뜁니다.
- 크리스탈은 평소에도 아주 살짝 빛납니다 (`M_BlockBase` 머티리얼 설정).

### 이동 표시등
- `Move`가 Patrol 계열이면 블록 아래 `SM_Floor_Plain_Light`(표시등)가 보입니다. `Fixed`/`Physics`면 숨겨집니다. 움직이는 블록인지 한눈에 알 수 있게 하는 표시입니다.

### Move
| 값 | 동작 |
|---|---|
| `Fixed` | 제자리 고정 |
| `Physics` | 물리 적용. 떨어지고 밀리고 잡을 수 있음 |
| `PatrolReturn` | 경유지를 끝까지 간 뒤 역순으로 되돌아옴 (A→B→C→B→A) |
| `PatrolRotation` | 마지막 경유지 다음 첫 경유지로 이어서 순환 (A→B→C→A) |
| `PatrolRestart` | 마지막 경유지에서 처음 위치로 순간이동 후 다시 시작 |

### MovePoint 설정 방법
`Move`가 Patrol 계열일 때 블록이 지나갈 경유지 목록입니다.

1. 블록을 선택하고 Details의 `MovePoint` 배열에서 + 를 눌러 경유지를 추가합니다.
2. 뷰포트에 경유지마다 작은 다이아몬드 모양 위젯이 나타납니다. 이것을 끌어서 위치를 잡습니다. (Details에서 X/Y/Z 숫자를 직접 입력해도 됩니다.)
3. 블록은 배열 순서(0 → 1 → 2 …)대로 이동합니다. 순서를 바꾸려면 배열 칸을 위아래로 옮기세요.

- 좌표는 블록 기준 상대 위치입니다. (0, 0, 300)은 "블록에서 위로 300". 그래서 블록을 옮기면 경로도 같이 따라 움직입니다.
- 블록을 회전하거나 크기를 바꾸면 경로도 같이 회전·확대됩니다. 게임 시작 시 한 번 월드 좌표로 바꿔 두기 때문에, 이동 중에는 경로가 블록을 따라가지 않습니다.
- 속도는 `MoveSpeed`(초당 이동 거리)로 일정하게 움직입니다. 경유지 사이가 멀수록 오래 걸립니다.
- `Move`가 `Fixed`나 `Physics`면 `MovePoint`는 무시됩니다.

### 6-2. 색별 능력

능력 발동 흐름 (공통)
1. 빛을 계속 비추면 게이지가 차오름 (색마다 충전 시간이 다름. Green은 0.2초로 빠름)
2. 다 차면 능력 시작
3. 빛이 떠나면 일정 시간 유지되다 종료 → 쿨타임

> 충전 / 유지 / 쿨타임 시간은 각 블록마다 바꿀 수 없고, `AvilityConfig` 함수에 색별로 고정되어 있습니다.

Red — 폭발 (즉시 발동, 유지 없음)
- `Physics`: 블록 자신이 튕겨 나감
- 그 외: 주변 물체와 플레이어를 밀어냄

| 변수 | 설명 | 기본값 |
|---|---|---|
| `InnerRadius` | 이 반경 안은 폭발력 100% | 200 |
| `OuterRadius` | 이 반경 밖은 0% (사이는 거리에 따라 감쇠) | 1250 |
| `ExplosionForce` | 주변 물체를 밀어내는 힘 (`Physics`가 아닐 때) | 2500 |
| `PushForce` | 블록 자신이 밀려나는 힘 (`Physics`일 때) | 2000 |
| `Exp_PlayerForce` | 플레이어에게 적용되는 힘 | 2000 |

Blue — 당기기 (즉시 발동, 유지 없음)
- `Physics`: 블록이 플레이어 쪽으로 끌려옴
- 그 외: 플레이어가 블록 쪽으로 끌려감

| 변수 | 설명 | 기본값 |
|---|---|---|
| `MaxPullSpeed` | 블록이 끌려오는 최대 속도 (`Physics`일 때) | 3000 |
| `PlayerMaxPullSpeed` | 플레이어가 끌려가는 최대 속도 (`Physics`가 아닐 때) | 2000 |

Green — 정지
- `Physics`: 물리를 꺼서 공중에서도 멈춤
- Patrol: 이동을 멈춤
- 튜닝 변수 없음

Yello / SkyBlue — 크기 변화
- 충전이 끝난 뒤부터 서서히 커지거나(Yello) 작아지고(SkyBlue), 끝나면 서서히 원래 크기로

| 변수 | 설명 | 기본값 |
|---|---|---|
| `ChangeSpeed` | 크기 변화 속도 (공통) | 0.3 |
| `UpScale` | Yello: 몇 배로 커질지 | 2 |
| `DownScale` | SkyBlue: 몇 분의 1로 작아질지 (2 = 절반) | 2 |

Purple — 반투명 통과
- 서서히 반투명해지며 플레이어와 물체가 통과 가능. `Physics` 블록은 바닥·벽은 계속 막음 (떨어지지 않게)
- 반투명일 때는 빛(그림자)도 통과합니다
- 능력이 끝날 때 플레이어가 블록 안에 있으면 나갈 때까지 통과 상태를 유지합니다 (끼임 방지)
- 블록끼리 겹친 채로 끝나면 천천히 밀려나며 분리됩니다
- 튜닝 변수 없음

> 보라 `Physics` 블록을 바닥 아래로 떨어뜨리고 싶을 때
> - 보라 상태의 `Physics` 블록은 일반 메시(Static Mesh Actor)로 만든 바닥과 벽은 통과하지 못합니다. 월드 바닥을 뚫고 끝없이 떨어지지 않게 막아 둔 것입니다.
> - 대신 다른 능력 블록은 통과합니다. 그래서 블록이 빠져나가야 하는 바닥은 일반 메시로 깔지 말고, 능력 블록에 바닥 메시를 덮어 씌워서 깔아야 합니다.
> - 만드는 법: `BP_AvilityBlock` 배치 → `IsUserStaticMesh` 켜기 + `UserStaticMesh`에 바닥 메시 → `Move = Fixed`
> - 주의: 이 바닥도 능력 블록이라 빛을 받으면 능력이 발동합니다. `ColorMode = ReactOnly` + `UseColor`를 퍼즐에서 쓰지 않는 색으로 두면 바닥이 엉뚱하게 반응하는 일을 줄일 수 있습니다.
> - 예: 일반 바닥 위에 이렇게 만든 "능력 블록 바닥" 구간을 두면, 보라가 된 상자는 그 구간에서만 아래층으로 떨어집니다.

### 이렇게 만들 수 있어요
- 움직이는 발판: `IsUserStaticMesh` + 발판 메시, `Move = PatrolReturn`, `MovePoint`로 왕복 경로 지정
- 버튼으로 움직이는 발판: 위에 더해 `WaitTrigger` 켜기 + 버튼의 SignalTargets에 이 블록 추가 → 버튼을 눌러야 출발
- 발판을 밟는 동안만 움직이는 벽: 벽 메시 + `WaitTrigger` + 발판 연결 → 발판에서 내려오면 그 자리에서 멈춤
- 멈춰서 올라타는 발판: `WaitTrigger` + `StartMoving` + 버튼(`Togle`) → 계속 움직이다가 버튼을 켜면 멈춤
- 초록으로 멈추는 발판: `ColorMode = ReactOnly` + `UseColor = Green` + Patrol 발판 → 원하는 위치에서 손전등으로 멈춰 올라탐
- 보라 벽: `ColorMode = ReactOnly` + `UseColor = Purple` + `Fixed` + 벽 메시 → 빨강 맵 광원 + 파랑 손전등을 섞어야 통과
- 노란 계단: `ColorMode = ReactOnly` + `UseColor = Yello` + `UpScale = 3` → 블록을 키워서 높은 곳에 올라감
- 파란 운반 퍼즐: `ColorMode = ReactOnly` + `UseColor = Blue` + `Physics` → 블록을 당겨와서 발판 위에 올리기

## 7. BP_Hatch — 다락문

한쪽 모서리를 경첩으로 삼아 90도 회전하며 열리고 닫히는 판입니다. 바닥 뚜껑, 다락문, 들리는 다리 등에 씁니다. 수신 장치입니다.
빛이나 색 능력에는 반응하지 않습니다. 능력 블록과는 별개의 장치입니다.

### 설정
| 변수 | 설명 | 기본값 |
|---|---|---|
| `ChannelRequired` | 채널별 필요 신호 수 (0번 = 열기). 2 이상이면 AND | `0 → 1` |
| `WaitTrigger` | 켜면 신호형: 신호가 켜지면 열리고 꺼지면 닫힘. 끄면 반복형: 게임 시작부터 혼자 열림 → 대기 → 닫힘 → 대기를 반복 (신호 무시) | 꺼짐 |
| `IsDown` | 켜면 반대 방향(아래쪽)으로 열림 | 꺼짐 |
| `StartOpen` | 신호형(`WaitTrigger` 켬)에서 켜면 열린 채로 시작. 신호가 켜지면 닫히고 꺼지면 다시 열림 (반대 동작). 에디터에서도 열린 모습으로 보임. 반복형에서는 무시 | 꺼짐 |
| `UseUserStaticMesh` + `UserStaticMesh` | 켜면 `UserStaticMesh`로 외형 교체 | 꺼짐 / 없음 |
| `OpenTime` | 열리는 데 걸리는 시간(초). 닫히는 시간도 같음 | 1 |
| `HatchWait` | 반복형에서 끝까지 열리거나 닫힌 뒤 기다리는 시간(초) | 2 |

- 여는 각도는 90도로 고정입니다. 방향만 `IsDown`으로 고릅니다.
- 신호형은 열리는 도중에 신호가 꺼지면 그 각도에서 바로 닫히는 쪽으로 되돌아갑니다.

### 경첩 위치와 여는 방향
- 경첩은 메시의 −X 쪽 모서리(높이 가운데)에 있고, 메시의 Y축을 기준으로 회전합니다.
- 경첩이 어느 변에 올지는 액터를 Z축으로 회전시켜 정합니다. 예: Z 180이면 반대쪽 변이 경첩이 됩니다.
- 외형은 `UseUserStaticMesh`를 켜고 `UserStaticMesh`에 메시를 넣어 바꿉니다. 경첩 위치는 그 메시의 크기를 기준으로 자동 계산됩니다.
- 레벨에는 액터를 닫힌 기준으로 배치하세요. `StartOpen`을 켜면 열린 모습은 자동으로 보여 줍니다(액터 자체를 돌려서 열린 모양을 만들지 마세요).

### 이렇게 만들 수 있어요
- 발판으로 여는 뚜껑: 발판의 SignalTargets에 다락문 추가 → 발판을 밟는 동안 열림
- 함정 바닥: `IsDown` 켜기 + 버튼(`JustOn`) 연결 → 버튼을 누르면 바닥이 아래로 열려 떨어짐
- 타이밍 통로: `WaitTrigger` 끔 → 혼자 열리고 닫히는 문 사이로 타이밍 맞춰 통과
- AND 다리: `ChannelRequired` `0 → 2` + 버튼(`Togle`) + 발판 → 둘 다 켜야 다리가 내려옴

## 8. 조합 예시 모음

| 퍼즐 | 구성 |
|---|---|
| 기본 문 | 버튼(`Togle`) → 문 |
| 타임어택 | 버튼(`Timed`, 3초) → 문 |
| 두 사람 몫 | 발판 A + 발판 B → 문(`ChannelRequired` `0 → 2`). 하나는 플레이어, 하나는 블록 |
| 조명 켜고 색 섞기 | 버튼(`Togle`) → 빨강 광원(`StartOn` 끔). 광원 아래 `ReactOnly` + `UseColor = Purple` 벽. 조명을 켜고 파랑 손전등으로 비춰 통과 |
| 색 금고 | 버튼(`ReOn`) → 광원(`ChangeColor` / `Rotate`). 광원이 초록일 때 손전등 빨강을 더하면 노랑 → 블록이 커져서 길이 열림 |
| 고유색 블록 | 능력 블록(`OwnColor`, `UseColor = Red`). 파랑으로 비추면 보라(통과), 초록으로 비추면 노랑(커짐) → 같은 블록을 손전등 색으로 다르게 사용 |
| 출발하는 엘리베이터 | 발판 → 능력 블록(발판 메시, `PatrolReturn`, `WaitTrigger`). 발판을 누르는 동안 위아래 왕복 |
| 함정 바닥 | 버튼(`JustOn`) → 다락문(`IsDown`, `WaitTrigger`). 누르면 바닥이 아래로 열림 |
| 한 번에 여러 장치 | 버튼 하나의 SignalTargets에 문 + 광원 + 움직이는 벽을 모두 넣기 |

## 9. 프로젝트 설정 / 주의사항

### 반드시 있어야 하는 설정
| 위치 | 설정 | 없으면 |
|---|---|---|
| `Config/DefaultEngine.ini` | 콜리전 Object Channel `LightCencer` (기본 응답 Overlap) | 맵 광원 감지 박스가 동작하지 않음 |
| `Config/DefaultEngine.ini` | `r.VolumetricFog.HistoryWeight=0` | 빛이 움직일 때 안개 잔상 |

### 흔한 실수
- 맵 광원만 비췄는데 능력이 안 나가요 → 플레이어가 광원 근처(`PlayerRange` 8000 안)에 있는지, 블록 `ColorMode`/`UseColor`가 광원 색과 맞는지 확인하세요.
- 버튼을 두 번 눌러야 색이 바뀌어요 → Rotate 광원에는 `Togle`이 아니라 `ReOn` 버튼을 쓰세요.
- 버튼이 안 눌려요 → `UseStaticMesh`로 바꾼 메시에 콜리전이 있는지 확인하세요.
- 맵 광원이 블록을 못 잡아요 → 블록 메시의 Generate Overlap Events가 켜져 있는지, `PlayerRange`가 0이 아닌지 확인하세요.
- 새 블록 메시가 투명하게 안 보여요 → 그 메시의 Nanite를 끄세요.
- 콜리전 Visibility 채널은 건드리지 마세요. 빛 판정 레이가 이 채널을 씁니다.

### 에디터에서 범위 확인
- 맵 광원을 선택하면 주황색 상자(감지 박스)가 보입니다. 판정 범위를 확인할 때 쓰세요.
- 뷰포트에서 Alt + C를 누르면 콜리전 표시를 켜고 끌 수 있습니다.
